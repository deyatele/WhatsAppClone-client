# Расскажи и ... - Веб-клиент

## Описание проекта

Расскажи и ... - это современное веб-приложение для обмена мгновенными сообщениями, которое имитирует функциональность популярного мессенджера WhatsApp. Приложение реализовано с использованием стека технологий Next.js и предоставляет полный набор возможностей для общения, включая текстовые сообщения, голосовые и видео звонки, шифрование, и систему аутентификации.

## Особенности

- **Обмен текстовыми сообщениями** - безопасный обмен сообщениями в реальном времени
- **Голосовые и видео звонки** - интеграция WebRTC для прямых вызовов между пользователями
- **Демонстрация экрана** - возможность делиться своим экраном во время вызовов
- **Шифрование на стороне клиента** - сквозное шифрование на основе криптографических ключей
- **Многопользовательские чаты** - поддержка групповых разговоров
- **Поддержка эмодзи** - богатый редактор сообщений с эмодзи
- **Адаптивный дизайн** - оптимизирован для мобильных устройств и настольных компьютеров
- **Управление профилем** - регистрация, вход и управление пользовательскими данными

## Технологический стек

### Frontend
- **Next.js 15** - фреймворк для универсального React-приложения
- **React 19** - библиотека для создания пользовательских интерфейсов
- **TypeScript** - строгая типизация
- **Tailwind CSS** - современный фреймворк для стилей
- **Zustand** - управление глобальным состоянием
- **Socket.IO Client** - для реального времени связи
- **WebRTC** - для голосовых и видео звонков
- **Lexical** - продвинутый редактор текста
- **UUID** - генерация уникальных идентификаторов

### Аутентификация и безопасность
- **JWT (JSON Web Tokens)** - для аутентификации
- **JWE (JSON Web Encryption)** - шифрование данных
- **Crypto API Browser** - создание ключевых пар на стороне клиента
- **Zod** - валидация данных

### Связь в реальном времени
- **WebSocket (через Socket.IO)** - для двусторонней связи в реальном времени
- **TURN/STUN-серверы** - для обеспечения связи через NAT и брандмауэры

### Ключевые компоненты

#### Хранилище Zustand
- Централизованное управление состоянием приложения
- Состояния для активных чатов, сообщений, вызовов, потоков и т.д.
- Поддержка пагинации, состояния загрузки и подключения к чатам

#### Провайдеры
- `UserProvider` - управление информацией о текущем пользователе
- `SocketProvider` - подключение и события через WebSocket
- `ToastProvider` - уведомления пользователей
- `ModalProvider` - управление модальными окнами

#### Криптография
- Генерация и хранение RSA ключевых пар на клиенте
- Шифрование сообщений с использованием открытого ключа получателя
- Расшифровка сообщений с использованием закрытого ключа отправителя
- Безопасное хранение ключей в IndexedDB

#### WebRTC
- Интеграция вызовов через WebRTC
- Поддержка передачи голоса и видео
- Возможность демонстрации экрана
- Управление ICE-кандидатами и перезапуском соединений
- Использование TURN-серверов для обхода NAT

## Установка и запуск

### Предварительные требования

- Node.js >= 18.x
- npm или yarn

### Установка зависимостей

```bash
npm install
```

### Настройка переменных окружения

Создайте файл `.env.local` в корне проекта и добавьте следующие переменные:

```env
# URL вашего API-сервера
API_URL=https://your-api-domain.com

# JWT секрет для верификации токенов
JWT_SECRET=your_jwt_secret_here

# TURN-сервер (если используется)
NEXT_PUBLIC_TURN_URL=your_turn_server_url
NEXT_PUBLIC_TURN_USERNAME=your_turn_username
NEXT_PUBLIC_TURN_CREDENTIAL=your_turn_credential
```

### Запуск приложения

#### Разработка
```bash
# Запуск в режиме разработки с HTTPS (требуется для WebRTC)
npm run dev
```

Приложение будет доступно по адресу: `https://localhost:3000`

#### Сборка для продакшена
```bash
npm run build
npm start
```

### Сертификаты HTTPS

Для полноценной работы WebRTC необходима работа по HTTPS. В проекте включены самоподписанные сертификаты в директории `/certs/` которые используются в режиме разработки.

Если вы хотите использовать свои собственные сертификаты:
1. Замените файлы `certs/cert.pem` и `certs/key.pem`
2. Или обновите `next.config.ts` для использования других сертификатов

## Использование

### Регистрация и вход
1. Посетите `/register` для создания нового аккаунта
2. Введите номер телефона, пароль и имя
3. После регистрации вы автоматически войдете в систему
4. Для входа в существующий аккаунт посетите `/login`

### Общие действия
- **Навигация по чатам** - список чатов отображается слева
- **Отправка сообщений** - используйте поле ввода внизу окна чата
- **Добавление эмодзи** - щелкните по значку эмодзи рядом с полем ввода
- **Вызовы** - нажмите на значок вызова для начала аудио/видео вызова
- **Демонстрация экрана** - во время вызова нажмите значок "поделиться экраном"

### Безопасность
- Все сообщения шифруются на стороне клиента с использованием RSA ключей
- Приватные ключи хранятся в зашифрованном виде в IndexedDB с использованием пароля пользователя
- Расшифровка сообщений происходит только на стороне получателя
- Использование AES-GCM шифрования с PBKDF2 деривацией ключей
- Сохранение только зашифрованных версий приватных ключей, без хранения в открытом виде
- Для аутентификации используются JWT токены с автоматическим обновлением

## API-маршруты

### Аутентификация (`/app/api/auth/`)
- `POST /api/auth/validate-password` - проверка пароля

### Чаты (`/app/api/chats/`)
- `GET /api/chats` - получить список чатов пользователя
- `POST /api/chats` - создать новый чат
- `DELETE /api/chats/[id]` - удалить чат

### Сообщения (`/app/api/messages/`)
- `GET /api/messages/[chatId]` - получить сообщения из чата
- `POST /api/messages` - отправить сообщение
- `PUT /api/messages/[id]` - обновить сообщение
- `DELETE /api/messages/[id]` - удалить сообщение

### Пользователи (`/app/api/users/`)
- `GET /api/users/me` - получить информацию о текущем пользователе
- `POST /api/users/register` - регистрация нового пользователя

### TURN-сертификаты (`/app/api/turn-credentials/`)
- `GET /api/turn-credentials` - получить учетные данные для TURN-сервера

## Безопасность

### Шифрование на стороне клиента
- Генерация пары RSA-ключей при регистрации
- Шифрование сообщений с использованием открытого ключа получателя
- Хранение закрытого ключа в зашифрованном виде в IndexedDB с использованием пароля пользователя
- Расшифровка сообщений только на стороне получателя
- Использование AES-GCM шифрования с PBKDF2 деривацией ключей
- Сохранение только зашифрованных версий приватных ключей, без хранения в открытом виде

### Аутентификация
- JWT-токены для аутентификации
- Автоматическое обновление токенов
- Защита всех маршрутов с помощью middleware
- Проверка пароля при каждом запуске приложения

### Защита данных
- Строгая типизация с использованием TypeScript
- Валидация всех входящих данных с использованием Zod
- Санитизация и очистка вводимых данных

## Устранение неполадок

### Проблемы с WebRTC
- Убедитесь, что вы используете HTTPS (требуется для WebRTC)
- Проверьте настройки брандмауэра и антивируса
- Проверьте конфигурацию TURN-сервера в переменных окружения

### Проблемы с аутентификацией
- Убедитесь, что `JWT_SECRET` правильно установлен в переменных окружения
- Проверьте, что сервер аутентификации работает и доступен по указанному URL

### Проблемы с подключением
- Проверьте сетевое подключение
- Убедитесь, что сервер API доступен
- Проверьте логи в консоли браузера на наличие ошибок
